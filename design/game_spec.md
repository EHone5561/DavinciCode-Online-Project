# 다빈치 코드 (Davinci Code) — 텍스트 게임 설계 문서

> 이 문서는 텍스트 기반 1차 구현을 위한 설계 명세다.
> 게임 룰은 실제 보드게임 '다빈치 코드'를 기준으로 하되,
> 본 프로젝트에서 명시한 몇몇 부분은 **변형 룰**로 별도 표기한다.
>
> 이후 GUI / 네트워크(server·client·ai) 확장 시 이 문서를 기준으로 삼는다.

---

## 0. 목표 아키텍처 (View 분리 확정)

- `모델(순수 로직)` : Card / Table / Player / Game + 한 턴 진행 규칙
- `View(입출력)` : **화면 표시(print)와 사람 input을 전부 담당.** GUI 확장 지점.
- `컨트롤러/게임 루프` : Game의 상태 진행을 View와 연결해 한 판을 돌림.

**결정 분리 원칙**
- CPU 의사결정 : 모델(Player/AI)이 생성
- 사람 입력  : **View 에서 받아** 모델(Player/Game)에 전달
  → 사람의 (흑 카드 수·추측 입력) 을 View가 수집.

클래스 간 참조 방향
```
View ──(사람 입력 요청/결과 표시)──▶ Controller
Controller ──▶ Game(진행상태/규칙) ──▶ Player/Table
```
모델은 input()/print()를 직접 호출하지 않는다.

## 1. 게임 개요

- 대상 인원 : **2 ~ 4명** (본 문서 1차는 사람 1 + CPU로 진행, 추후 네트워크 확장)
- 카드 매수 : 숫자 0~11 × 색(흑/백) 24장 + 조커(흑/백) 2장 = **총 26장**
- 성격 : 숫자 추리 + 라인 배치 보드게임

### 승패 요약 (변형 룰 — 본 프로젝트 확정)
- **자기 카드가 전부 공개(뒤집힘)된 시점에 탈락**
- **탈락한 순서대로 꼴찌(=등수 부여) → … → 최후 생존자 1등**
- 즉 4인 게임이면 4등, 3등, 2등이 순서대로 정해지고, 마지막 남은 1명이 1등.

---

## 2. 카드 모델

| 항목 | 내용 |
|---|---|
| 숫자 카드 | value 0~11 (12종), 색은 흑/백 |
| 조커 | value 없음(None), 색은 흑/백 |
| 표기 | 숫자 1자리 + 색 1자리 → `5b`, `7w`, `ab`(10흑), `bw`(11백) |
| 조커 표기 | 공개 시 `Jb`, `Jw` |

### 카드 정렬/순서 규칙
- 정렬 : 조커를 가장 앞쪽에, 그 뒤 숫자 0→11 오름차순.
- 같은 숫자면 **흑이 백보다 앞** (예: 0b, 0w, 1b, 1w, ...).
- 색은 항상 공개 정보다 (뒤집혀 있어도 흑/백은 구분 가능).
  숫자 값만 비밀이며, 조커 여부도 공개되기 전엔 비밀.

## 3. 플레이어와 화면 (텍스트 UI)

### 3-1. 라인(bank) 개념
- 각 플레이어는 **자기 카드들을 일렬로 배치**한다. 이를 '라인'이라 부른다.
- **자기 눈에도, 상대 눈에도 기본은 "뒤집힌/색만 보이는" 카드**로 시작한다.
- 공개된 카드만 그 자리에 값+색이 드러난다.

### 3-2. 색 구분 표기 (본 프로젝트 시각 규약)
> **모든 카드는 색이 항상 보인다.** 값만 숨겨진다.

| 상태 | 내가 볼 수 있는 것 | 표기 |
|---|---|---|
| 비밀 카드 (색만 공개) | 색 | 흑 `■` / 백 `□` |
| 공개 카드 | 값 + 색 | `5b`, `7w`, `Jw` |
| 내 카드 | 항상 값 + 색 | `Jb`, `0w`, `4b` |

### 3-3. 화면 배치
- 상대 줄은 **가로로 나열**해 각 자리를 보여준다.
- GUI(판 형식)는 이후 단계에서 진행한다. (본 단계는 텍스트 가로 나열)

#### (추가) "방금 뽑은 카드" 표식
- 이번 턴에 패산에서 뽑은 카드는 **본인이 값·위치를 인지**한 상태다.
- 오답 벌칙이 "이번에 뽑은 그 카드 공개" 이므로, 본인 눈 화면에서 그 카드를
  값 오른쪽에 `*` 를 붙여 **다른 기존 패와 구분**한다.
  - 예) `자리3: 2b*`  ← 이번 턴에 뽑은 카드(2흑)
- `*` 는 **자기 눈 화면에서만** 표시된다. (상대 에게까지 공유정보가 갈 필요는 없다)

```
══════════ 다빈치 코드 — 턴 4 ══════════
공용 덱 남은 장수 : 12장

 [상대] CPU1   (살아있음 · 비밀 2장 · 공개 2장)
   자리: 1■  2■  3:5w(공개)  4:2b(공개)

 [상대] CPU2   (살아있음 · 비밀 3장 · 공개 1장)
   자리: 1□  2:1w(공개)  3□  4■

---------- <나의 패 : 나만 값이 보임> ----------
   자리: 1Jb  2:0w  3□  4:8b
-----------------------------------------------
 명령 입력> 뽑기 | 추측 [상대] [자리] [카드] | 상태
```

## 4. 게임 진행 규칙

### 4-1. 시작 (세팅)
- 인원당 기본 패수
  - 2~3인 : 각 **4장**
  - 4인 : 각 **3장**
- 시작 시 사람은 **가져갈 검은 카드 수**를 정할 수 있다 (등 뒤에 패 깔기, 무작위).
  - 나머지는 흰 카드로 받는다. (문제: 동시 배치 순서 — 검은 카드만 먼저 줄지 / 전부 주고 섞을지 — 시작 룰 디테일 확정 필요)
- 각자 카드는 **라인에 정렬 배치**된다. 자기 눈엔 값이 보이고, 상대 눈엔 색만 보인다.

### 4-2. 차례(Turn) 진행

**패산(deck)이 남아 있는 경우 — 본인 턴 시작 시 반드시 카드 1장을 뽑아야 한다.**

**(A) 카드 뽑기 (의무)**
- 패산에서 1장 뽑아 라인에 정렬로 끼워 넣는다.
- 뽑은 카드의 **값·위치를 본인이 인지**한다 (구분 표식 `*`).
- 이후 지목(추측)으로 이어진다.

**(B) 상대 지목 (추측)**
- 본인 라인에서 **값이 보이는 카드(본인이 아는 카드)를 골라**
- 특정 상대의 **특정 자리**가 그 값인지 외친다.
- 예) "CPU1의 2번째 자리 = 5b"
- **조커를 값으로 외칠 수는 없다.** (값 = 조커라고 지목 불가)

**패산이 없으면(소진 후)** — 뽑기 없이 바로 (B) 지목만 한다.


### 4-3. 추측 판정

맞히려는 상대가 해당 자리 카드를 공개하여 확인한다.

- **정답** : 그 상대의 해당 패가 **공개 상태로 고정**된다.
  - 이후 **추가 지목 여부는 공격자(지목한 사람)의 의사**에 따른다.
  - (맞히는 한, 연속으로 다른 지목 가능 — 무제한 / 턴은 계속)
- **오답** :
  - **패산 남아있을 때** : 이번 턴에 **뽑았던 그 카드(`*` 카드)** 를 본인 줄에서 **공개** → 턴 종료
  - **패산 없을 때** : **본인의 임의의 패**(본인이 고름)를 하나 **공개** → 턴 종료

> 즉, 오답 벌칙은 "뽑아온 카드(있는 경우)" 혹은 "자발적 공개 1장(덱 소진 시)" 이고, 후자는 항상 생기며 스스로 어떤 카드를 뒤집을지 고른다.


### 4-4. 탈락 / 순위 / 종료 (확정 룰)
- 자기 **모든 카드가 공개**되면 → **탈락**.
- 탈락한 순간 그 플레이어는 게임에서 빠지고 등수가 정해진다.
- **탈락 순서 = 등수** (4인 기준 : 처음 탈락 4등 → 다음 3등 → …).
- **최후 1명이 남으면 그 사람이 1등**이며 게임 종료.
- CPU 가 살아있으면 CPU 끼리도 계속 진행한다. (마지막 생존자가 1등)

## 5. 디테일 확정 기록 (기존 미확정 목록 → 해소)

1. **시작 배치 규칙** : 사람이 가져갈 검은 카드 수를 입력받는다(흑 일부만 먼저, 나머지 백으로).
   - 실제 구현은 "흑 카드 black_count 장 + 백 카드 나머지" 를 받아 라인에 정렬.
   - (서로 섞이지 않게, 사람은 검은 카드 개수만 정하는 시나리오로 단순화)
2. **추측 연속** : 맞히는 동안 **무제한** 지속 가능. 공격자 의사에 따라 다음 지목 또는 턴 종료.
3. **오답 벌칙** :
   - 덱 남음 → **이번에 뽑은 카드(`*`) 공개** (유일 명확한 공개 대상)
   - 덱 소진 → **자기 임의의 패 1장을 본인이 고르고 공개**
4. **무승부 / 종료** : 최후 1명 남으면 즉시 게임 종료(1등). 다른 처리는 불필요.
5. **덱 소진 후** : 뽑기 없이 **지목만** 가능. 오답 시 임의 공개 1장.

> 이로써 게임 진행 룰이 완전히 정의되었다. 이후 코드는 이 규칙을 그대로 구현한다.

## 6. 조커(Joker) 시스템 (확정 — 실제 추리 방해 카드)

### 6-1. 조커의 철학
조커는 '방패'로 막는 카드가 아니라, **정렬된 숫자 패 사이의 '임의의 칸'에 끼어들어
공격자의 '오름차순 위치 역추리'를 헷갈리게 하는 카드**다.

### 6-2. 라인(패 배치) 모델 — 조커가 만드는 '구간'
- 각 라인은 **숫자 카드(값 오름차순, 동값이면 흑이 왼쪽) + 사이사이 끼어 있는 조커들**로 구성.
- 조커는 스스로 정렬되지 않고 **자기 칸(숫자 카드 사이) 위치를 유지**한다.
- 값순 정렬은 조커가 아닌 숫자 카드들에만 적용된다.

### 6-2b. [확정] 일반 숫자 카드 삽입 — "조커 사이로 정렬되지 않는다"
새 숫자 카드 N을 뽑으면 값 오름차순 자리를 구하되, 다음 원칙이 지켜진다.
- **N 은 조커와 조커 사이로 정렬/삽입되지 않는다.** (조커는 이동하지 않음)
- N 이 놓일 자리가 **조커에 인접**하면 그 조커에게 "앞(왼쪽)/뒤(오른쪽)" 을 묻는다.
- 선택 후 **다른 조커에 또 인접**하게 되면 다음 조커에게도 차례로 앞/뒤를 묻는다.
  (연달아 조커 k 개면 최대 k 회 순차 질문 가능)
- 조커에 안 부딪치면(그 값 자리에 조커가 없으면) 질문 없이 값 자리에 자동 삽입.

**동작 예시**
1. `[2b, Jb, 5w]` + `3b`(3) : 3 은 2·5 사이, Jb 인접 → "Jb 앞/뒤?" 1회
2. `[1b, Jb, Jw, 4w]` + `5b`(5) : 5 는 4 우측 → 조커 없이 자동 `[1b,Jb,Jw,4w,5b]` (질문 없음)
3. `[2b, Jb, Jw, 6w]` + `4w`(4) : 4 는 조커 뭉치 사이로 못 감 → Jb 에게 물어봄
   → 뒤라 하면 Jw 에게 또 물어봄 → 뒤라 하면 `[2b,Jb,Jw,4w,6w]`

### 6-3. 조커 삽입 위치 (사용자 지정 — 좌표 체계 확정)
- 조커는 **오직 (도중) draw 로만** 패에 들어온다. (초기 분배 N장엔 조커 없음)
- 조커를 뽑으면, 플레이어(사람=View 입력 / CPU=랜덤)가 **삽입 슬롯 번호**를 정한다.
- 슬롯 번호 의미 (카드가 M장일 때 슬롯은 0~M, 총 M+1개):
  - `0` = 맨 앞,  `n` = n번째 카드 **뒤**,  `M` = 맨 뒤
  - 예) `[2b, 4w]`에서 `2`입력 → `[2b, 4w, Jb]`,  `1` → `[2b, Jb, 4w]`, `0`→`[Jb,2b,4w]`
  - 범위 밖(3 이상 등) → 재입력 요구.
- 한 번 삽입한 조커의 자리는 이후 일반 카드가 추가돼도 **유지**된다.
- 동일 값 흑/백 방향 : **흑이 왼쪽**. (예 0b, 0w, 1b, 1w …)

### 6-5. 조커 추측 허용
- 추측값 후보에 **`Jb`, `Jw` 포함**. (값 형식에 조커도 유효)
- 특정 상대의 특정 자리 카드가 조커인지 `Jb/Jw`로 외쳐 정답이면 그 자리 공개.
- (기존 뼈대에서 조커 추측을 금지하던 처리 제거 필요)

### 6-6. 뼈대에 반영할 구현 포인트
- `Player` 라인 정렬(`sort_hand`)를 "조커는 위치 유지, 숫자 카드만 정렬"로 재정의.
- 조커 삽입 메소드 : 슬롯 0~M 사이에서 삽입.
- draw 시 조커면 슬롯 입력(사람) / 랜덤(CPU).
- 추측 파서·검증·판정에 조커 값 허용.

## 6. (참고) 추후 확장 계획

- 사람 1명 + CPU / 추후 2~4인 네트워크
- 파일 분리 예정 : `server.py`(게임 중앙 판정), `client.py`(사람 입력), `ai.py`(CPU 추론)
- GUI 단계에서 "판 형식" 라인 표시로 전환
